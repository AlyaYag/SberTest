# Описание репозитория

## Данный репозиторий является тестовым заданием для ванасии аналитика данных в компанию Сбербанк. Далее представлены описания предложенных задачи по ML и SQL. Результаты находятся в соответсвующих дочерних директориях.

## Описание задач по ML

### Задание 1. Классификация

Сгенерируйте синтетический набор данных для бинарной классификации с двумя признаками. Постройте и сравните модели логистической регрессии, SVM, дерева решений и случайного леса. Для каждой модели выполните подбор гиперпараметров с помощью сеточного поиска, а качество оцените на тестовой выборке через коэффициент Джини (преобразование из AUC). Визуализируйте данные и не забудьте масштабировать признаки перед обучением моделей, чувствительных к масштабу.

---

### Задание 2. Регрессия с бэггингом

Создайте синтетический датасет для задачи регрессии, где целевая переменная является линейной комбинацией десяти признаков с добавлением гауссовского шума. Обучите ансамбль бэггинга на основе линейной регрессии и оцените его качество с помощью MSE и R². Проведите диагностику модели: проверьте мультиколлинеарность признаков (корреляционная матрица и VIF), проанализируйте остатки (графики, распределение, тест на нормальность) и оцените важность признаков через усреднённые коэффициенты базовых моделей.

---

### Задание 3. Прогнозирование временного ряда

Сгенерируйте синтетический временной ряд, содержащий тренд, синусоидальную сезонность и случайный шум. Постройте две прогнозные модели: авторегрессию (порядок лага выберите автоматически по AIC) и экспоненциальное сглаживание (ETS) с учётом тренда и сезонности. Оцените точность прогнозов на тестовом участке с помощью MAE и RMSE. Визуально сравните прогнозы обеих моделей с фактическими значениями на тестовой выборке.


## Описание задач по SQL

### Задача 1. Активность пользователей  
Необходимо написать SQL-запрос, который возвращает список пользователей с их ролями и количеством активностей за последний месяц. Учитываются только активности, зарегистрированные в указанный период. Результат сортируется по убыванию количества активностей.

---

### Задача 2. Фильтрация транзакций  
Требуется разработать SQL-запрос для сопоставления кредитных траншей и расходных операций клиентов за 2024 год. Сопоставление выполняется по двум условиям: (1) суммы транзакции в точности равны сумме транша в пределах 10 дней после его даты; (2) если точного совпадения нет, для каждого транша выбираются все расходные операции, чья накопленная сумма превышает сумму транша (включая превысившую операцию). Результат должен содержать все детали транзакций и соответствующих траншей.

---

### Задача 3. Оптимизация SQL-запроса  
Дан неэффективный запрос, содержащий множественные коррелирующие подзапросы для подсчёта счетов, балансов, депозитов и снятий по каждому клиенту. Требуется оптимизировать его, заменив подзапросы на агрегацию с группировкой, и предоставить оптимизированную версию с кратким пояснением внесённых изменений.
